# QN85DD compatibility check

This guide prepares the port for **QN75QN85DDFXZA** with main firmware
**T-PTMDAKUC-0090-2130.0**. These two values were read from the owner's About
TV screen. No diagnostic or installation command has been run on this TV yet.

The [device profile](../profiles/qn75qn85ddfxza-2130.0.json) currently permits
**inventory collection**. Root access, launcher installation, cleanup, and
operation after a restart remain unverified. The profile keeps those operations
disabled while the installed runtime, app packages, and interfaces are checked.

## Prepare the computer and TV

Run the check from a computer connected to the **same local network as the
TV**. A remote cloud workspace cannot directly reach the TV's local address.

The computer needs:

- Python 3.12 or later.
- Samsung's SDB tool, installed separately through the supported
  [Tizen SDK CLI installer](https://samsungtizenos.com/tools-download/).
- This updated Quiet Tizen checkout.

The diagnostic command requires no .NET SDK, compiled root payload, or launcher
build. Open a terminal in the checkout's top-level directory.

Use Samsung's [Developer Mode connection instructions](https://developer.samsung.com/smarttv/develop/getting-started/using-sdk/tv-device.html):

1. Open Smart Hub, then Apps and App Settings.
2. Enter `12345` with the remote or its on-screen number keypad.
3. Turn Developer Mode on.
4. Enter the computer's local IPv4 address as the host computer address.
5. Confirm and restart the TV.

Menu labels can vary. Read the TV's local IPv4 address from its network settings.
The TV address and computer address serve different purposes; enter each in the
place specified below.

On a compact Samsung Smart Remote without physical number keys, press its
`123`/Number or combined Settings/Number/Color button while App Settings is
open. If a row of shortcuts appears, select `123`, then use the directional
pad and Select button to enter `1`, `2`, `3`, `4`, `5`; choose Done if shown.
Samsung documents the [on-screen number pad](https://developer.samsung.com/smarttv/design/input-methods.html).

### Windows preparation

1. Install [Python for Windows](https://www.python.org/downloads/windows/) if
   needed. Open PowerShell and run `py -3 --version`; the version must be 3.12
   or later. If only `python` is available, use `python` instead of `py -3` in
   the commands below.
2. Download the official
   [Tizen SDK CLI Windows 64-bit installer](https://download.tizen.org/sdk/Installer/tizen-sdk_10.0/web-cli_Tizen_SDK_10.0_windows-64.exe).
   Run it and choose `C:\tizen-studio` as the installation directory.
3. Verify the tool in PowerShell:

   ```powershell
   & "C:\tizen-studio\tools\sdb.exe" version
   ```

4. Connect the computer to the TV's network. Run `ipconfig` in PowerShell and
   find the IPv4 address of the active Wi-Fi or Ethernet adapter. Enter that
   computer address in the TV's Developer Mode settings, as described above.
5. Extract the updated Quiet Tizen ZIP. In File Explorer, open the `quiet-tizen`
   folder that contains `README.md` and `tools`. Type `powershell` in the address
   bar and press Enter to open PowerShell in that folder.

The [current SDK installation documentation](https://github.com/Samsung/tizen-docs/blob/master/docs/sdk-tools/baseline-sdk/setup/install-sdk.md)
supports the CLI installer. The [SDB documentation](https://github.com/Samsung/tizen-docs/blob/master/docs/sdk-tools/baseline-sdk/common-tools/smart-development-bridge.md)
places SDB in the SDK's `tools` directory. This diagnostic does not need a TV
extension, emulator, signing certificate, or .NET compiler.

## Run the diagnostic

Replace `TV_LAN_IP` with the TV's address. Keep the profile and firmware values
exactly as shown for this TV. Run this as one line on macOS or Linux:

```sh
python3 tools/tv.py --host TV_LAN_IP --profile profiles/qn75qn85ddfxza-2130.0.json --firmware T-PTMDAKUC-0090-2130.0 doctor --report .local/qn85dd-preflight.json
```

On Windows, paste this PowerShell helper. Enter the TV address and the computer
address when prompted. The computer address must match the one entered in the
TV's Developer Mode settings:

```powershell
$tvIp = (Read-Host "TV IPv4 address").Trim()
$pcIp = (Read-Host "Computer IPv4 address entered on the TV").Trim()
py -3 tools/tv.py --host $tvIp --callback-host $pcIp --sdb "C:\tizen-studio\tools\sdb.exe" --profile profiles/qn75qn85ddfxza-2130.0.json --firmware T-PTMDAKUC-0090-2130.0 doctor --report .local/qn85dd-preflight.json
```

If the SDK is installed elsewhere, change only the path after `--sdb`.
The helper can return exit code 2 when a prerequisite is not established;
return the report even if some checks are marked incomplete. If the command
stops before creating a report, return its error text.

To open the report's folder after it is created:

```powershell
explorer.exe .local
```

If SDB is installed in a location the tool does not find, add
`--sdb "ABSOLUTE_PATH_TO_SDB"` **before** `doctor`. On Windows this points to
`sdb.exe`. If the computer selects the wrong network interface, add
`--callback-host COMPUTER_LAN_IP` before `doctor`, replacing the placeholder
with the same local computer address configured in Developer Mode.

The helper connects only to the supplied TV address. It reads fixed diagnostic
fields through the existing SDB transport. It does not obtain root or change
persistent TV configuration. The transport can create temporary gate directories
and stage temporary command scripts.

## Review the report

The report is saved to `.local/qn85dd-preflight.json`. It records:

| Area | Evidence sought |
|---|---|
| Identity | Observed SDB model and declared About TV firmware |
| Runtime | Installed kernel, architecture, and .NET runtime evidence |
| Access prerequisites | Relevant file capabilities and archive-tool support |
| Launcher prerequisites | Candidate application files and native libraries |
| Configuration layout | Selected database schemas, where readable |

The report contains selected compatibility fields. It omits network addresses,
serial numbers, account identifiers, and raw diagnostic logs. Partial results are
saved when possible; unavailable or denied checks remain explicit. A missing
field requires investigation and does not mean its value matches the U8000F.

Return this report for the next port iteration. It identifies which components
can be reused and which need adaptation. Successful diagnostics establish
preflight observations; launcher behavior still requires building against the
actual TV libraries and testing on the TV.

## Why this access route is being investigated

The [upstream compatibility table](https://github.com/chris-ritsen/samsung-tv-root#tv-compatibility)
reports archive-launcher root access on a **QN55S90DAFXZA** using the same main
firmware string, `T-PTMDAKUC-0090-2130.0`. The associated
[S90D device record](https://github.com/splitcipher/couchroot/blob/main/docs/lab/devices/s90d/persistence.md)
documents root identity and cleanup checks. These are observations on another
model; they make this route worth checking without establishing QN85DD support.

That S90D record also reports rejection of a 495-byte inline SDB request and
success after staging it. This profile therefore uses a conservative **400-byte
inline request limit**. It is a computer-side transport setting, not a measured
hardware limit for this TV or evidence that root will work.

The QN85DD profile intentionally leaves operating system, kernel, runtime,
registry, and cleanup targets unspecified until this device supplies evidence.
The `0090` component of the displayed firmware is insufficient to fill them in.
